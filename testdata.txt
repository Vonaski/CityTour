6. Создаём главный demo tour

Вот этот тур лучше использовать дальше во всей демонстрации.

curl -i -X POST "$BASE_URL/api/tours" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Demo City Tour",
    "guideId": 1,
    "startTime": "2026-12-10T10:00:00",
    "endTime": "2026-12-10T13:00:00",
    "maxSeats": 5,
    "pricePerSeat": 100.00,
    "stops": [
      {
        "attractionId": 1,
        "visitOrder": 1,
        "stayMinutes": 60
      },
      {
        "attractionId": 2,
        "visitOrder": 2,
        "stayMinutes": 60
      }
    ]
  }'

Получишь новый ID. Допустим:

Location: /api/tours/23

Дальше обозначим:

TOUR_ID=23

Внимание: не копируй 23 вслепую. Используй ID из своего ответа.

Тур должен появиться как DRAFT, потому что новый Tour по ТЗ всегда создаётся в DRAFT.

8. Проверяем overlap Guide — BR-2

Теперь создаём другой Tour для того же Guide #1, но пересекающийся по времени.

Первый:

10:00 ───────── 13:00

Второй:

12:00 ───────── 15:00

Curl:

curl -i -X POST "$BASE_URL/api/tours" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Overlapping Tour",
    "guideId": 1,
    "startTime": "2026-12-10T12:00:00",
    "endTime": "2026-12-10T15:00:00",
    "maxSeats": 5,
    "pricePerSeat": 100.00,
    "stops": [
      {
        "attractionId": 3,
        "visitOrder": 1,
        "stayMinutes": 60
      },
      {
        "attractionId": 4,
        "visitOrder": 2,
        "stayMinutes": 60
      }
    ]
  }'

Ожидаем:

409
GUIDE_HAS_OVERLAPPING_TOUR

У тебя именно такой код уже проверялся. BR-2 требует запрещать пересечение, но разрешает границу, например 10:00–12:00 и 12:00–14:00.

11. Publish — BR-1 + BR-8
curl -i -X POST "$BASE_URL/api/tours/23/publish"

Ожидаем:

200
status: PUBLISHED

Здесь одновременно демонстрируешь:

минимум 2 stops;
visitOrder = 1..N;
уникальные attractions;
duration >= sum(stayMinutes).

Это именно BR-1 и BR-8.

12. Создаём Booking

Теперь главное.

curl -i -X POST "$BASE_URL/api/tours/23/bookings" \
  -H "Content-Type: application/json" \
  -d '{
    "customerName": "Demo Customer",
    "customerPhone": "+998901234999",
    "seats": 3
  }'

У нас:

pricePerSeat = 120
Registan = 50000
Gur-e-Amir = 30000
Bibi-Khanym = 25000

Сумма entry fee:

50000 + 30000 + 25000 = 105000

Цена одного места:

120 + 105000 = 105120

Три места:

105120 × 3 = 315360

То есть totalPrice должен быть 315360.00.

Это прямо BR-6:

seats × (pricePerSeat + sum(entryFee))

15. Отменяем Booking

После первого booking запомни его ID.

Например:

Location: /api/bookings/12

Тогда:

curl -i -X DELETE "$BASE_URL/api/bookings/12"

Ожидаем:

204 No Content

Важно сказать на защите:

DELETE здесь физически не удаляет booking. Он переводит его в CANCELLED, поэтому освободившиеся seats снова становятся доступными.

Это соответствует ТЗ: DELETE /api/bookings/{id} — отмена брони, а не удаление.

20. Attraction DELETE — BR-7

Берём Attraction, которая используется в DRAFT/PUBLISHED Tour.

Например:

curl -i -X DELETE "$BASE_URL/api/attractions/1"

Ожидаем:

409
ATTRACTION_USED_BY_ACTIVE_TOUR

Это BR-7: нельзя удалить объект, используемый DRAFT или PUBLISHED туром.

21. Statistics — обязательно показать
Guides

guideName
toursCount
totalHours

Причём только PUBLISHED tours, которые начинаются в заданном диапазоне. occupancyRate считается по sold seats / сумме maxSeats.

Attractions top
